# PRD: Named shares + OpenGraph previews

Status: done

Parent PRD: [`.scratch/scribblerig/PRD.md`](../scribblerig/PRD.md)

## Problem statement

ScribbleRig's serverless URL-share model is one of the product's defining
properties (parent PRD, user stories 29-33). But three real-world frictions
have surfaced as people try to share creations:

1. **No OpenGraph preview.** Today's shares put the scene in the URL
   *fragment* (`#…`), which crawlers (Twitter, Discord, Slack, Facebook)
   never see. Links land in chats and timelines as plain hostname + page
   title, with no image and no description. Sharers can't show their
   creation; recipients can't tell what's at the link.
2. **No naming.** A tinkerer can't say "here's my rolling-ball-launcher,"
   only "here's a URL." The product makes nothing visible about the
   creation outside the act of opening it.
3. **URL length.** Some scenes encode to 1.5–5 KB. Long enough to be
   mishandled by some chat apps, truncated by some link-preview crawlers,
   and ugly to look at.

The parent PRD's *Out of Scope* anticipates this third one specifically:
*"A future fallback (out of scope for v1) is a tiny key-value store that
holds the blob and returns a short id when a scene exceeds practical URL
length."* This feature delivers that escape hatch and uses it as the
backbone for the other two.

## Solution

A worker layer on top of today's serverless model. Two URL forms coexist:

- **`?s=<encoded>`** — today's behaviour, no backend dependency. The Share
  button still copies this for un-named scenes under a size cap. Backwards
  compatible with every link already in the wild (which use `#…` —
  reader-side falls back to it).
- **`/s/<id>`** — opaque 10-char ID backed by Cloudflare KV. The Share
  button mints this whenever the user names their creation, **or** when an
  un-named scene exceeds the URL-length cap.

The **scene itself owns the title** (`scene.title?: string`). It survives
autosave, copy/paste, and round-trips through both URL forms. Naming a
build is a property of the build, not of a particular share.

The **worker** serves either URL form to crawlers and browsers alike,
injecting `og:*` / `twitter:*` meta tags into the HTML head and rendering
an SVG thumbnail at `/og.svg?s=…` or `/s/<id>/og.svg`. The thumbnail is the
same hand-drawn doodle style as the canvas, generated by a DOM-free SVG
renderer that mirrors the canvas renderer's geometry decisions.

**Immutability** is a deliberate property: once minted, a `/s/<id>`
represents one frozen scene forever. To "update" you create a new share.
This lets `Cache-Control: immutable` apply uniformly to both HTML and SVG
responses; Cloudflare's edge absorbs traffic spikes for free; and we sidestep
all the editing-and-auth questions for v1.

## Architecture decision

See [ADR-0010](../../docs/adr/0010-shortlinks-and-worker-og.md) for the
shift from "URL-only, no backend" to "URL + optional KV fallback."

## In scope (v1)

- **Scene `title` field** on the design graph, sanitized (80-char cap,
  control chars stripped, no HTML), codec round-trip.
- **Pure SVG renderer** (`src/og/renderSvg.ts`) — DOM-free, mirrors canvas
  renderer geometry. Tested.
- **Title derivation** for un-named scenes (`"3 balls · 1 motor"`).
- **Cloudflare Worker** dispatching:
  - Static-asset pass-through for `/assets/*` (no per-request worker cost).
  - HTMLRewriter injection of OG meta + inline scene blob for `/?s=…`
    and `/s/<id>`.
  - SVG render at `/og.svg?s=…` and `/s/<id>/og.svg`.
  - Mint endpoint `POST /api/share` with per-IP rate limit and
    nanoid-based ID generation.
- **Cloudflare KV** as the shortlink store. One namespace, `SHARES`. Row
  shape: `{ sceneEnc, title?, createdAt }`.
- **Share URL change**: `?s=` becomes the default (was `#…`); both forms
  read on boot for backwards compatibility.
- **Naming UI** in a Share popover. Optional name field. Empty + small →
  `?s=` URL. Named or oversized → mint shortlink.
- **Auto-promotion at size cap** (~1500 chars) — even un-named oversized
  scenes silently get a shortlink with a derived title.
- **SPA hydration** via worker-injected `<script id="og-data">` blob —
  one round trip on `/s/<id>` visits.
- **PRD updates** to the parent (move KV fallback out of Out of Scope).

## Out of scope (deliberate v1 deferrals)

- **PNG output via resvg-wasm.** Twitter historically prefers PNG over SVG
  for card images; some other platforms reject SVG outright. SVG-only is a
  known trade-off for v1, addressed in a follow-up.
- **Dynamic title hints from scene content.** `deriveTitle` is straightforward
  enumeration in v1 ("3 balls · 1 motor"). Pattern detection ("rolling
  ball machine," "pendulum") is a separate quality bar.
- **View counts / "recently shared" / public gallery.** Data model
  accommodates additions; no UI in v1.
- **Editing a shortlink.** Immutability is a chosen v1 property. Editing
  is a meaningful feature with auth/ownership requirements; deferred.
- **Takedown / KV deletion.** Operational, defer until needed.
- **PNG/SVG content negotiation.** `/og` endpoint that picks format by
  `Accept` header is reachable once PNG is built.

## User stories

1. As a tinkerer, I want to name my creation, so that the link I share
   shows that name in chat and social previews.
2. As a tinkerer, I want a recipient to see a visual preview of my
   creation when I share the link, so that the share is enticing rather
   than blank.
3. As a tinkerer, I want my share URLs to stay short for named creations,
   so that I can paste them anywhere without truncation.
4. As a recipient, I want to open a `/s/<id>` link and see the same scene
   the creator built, with the right title, so that opening the link
   feels like opening *their* creation.
5. As a tinkerer, I want existing links (the `#…` URLs I've already
   shared) to keep working, so that nothing breaks for past shares.
6. As a tinkerer, I want my un-named oversized scenes to still produce a
   usable share URL automatically, so I don't have to think about URL
   limits.

## Acceptance criteria

- [ ] Naming a creation in the Share popover produces a `/s/<id>` URL
      backed by KV.
- [ ] Sharing an un-named under-the-cap scene produces today's `?s=`
      URL — no backend roundtrip.
- [ ] Sharing an un-named over-the-cap scene auto-promotes to a shortlink
      with a derived title.
- [ ] A crawler GETting `/?s=ENC` sees `og:*` / `twitter:*` meta tags
      with a derived title and an `og:image` pointing at `/og.svg?s=ENC`.
- [ ] A crawler GETting `/s/<id>` sees `og:*` / `twitter:*` meta tags
      with the stored title and an `og:image` pointing at
      `/s/<id>/og.svg`.
- [ ] OG SVG renders the scene in the doodle style, no DOM dependencies,
      `Cache-Control: public, max-age=31536000, immutable`.
- [ ] `POST /api/share` rate-limits to 10/min per IP (429 above).
- [ ] Static-asset requests bypass the worker entirely.
- [ ] Existing `#…` share URLs still load.
- [ ] Parent PRD updated.

## Implementation issues

Implementation is split into three sequential issues, each independently
pickup-able by a fresh agent:

- [Issue 01 — SVG OG for URL-shared scenes](issues/01-svg-og-for-url-shares.md):
  the foundation. Scene `title` field, SVG renderer, derived titles, worker
  routes, and the `?s=` URL switch. **Ships:** OG previews for every share,
  zero KV / backend state introduced.
- [Issue 02 — Named scenes with KV shortlinks](issues/02-named-scenes-kv-shortlinks.md):
  the storage layer. KV mint endpoint, `/s/<id>` resolution, rate limit,
  wrangler binding. **Ships:** the `/s/<id>` URL form works end-to-end via
  `curl`; no UI changes yet.
- [Issue 03 — Share popover with naming UI](issues/03-share-popover-naming-ui.md):
  the user-facing surface. Doodle popover, name input, copy UX, auto-
  promotion at size cap. **Ships:** users can name their creations.

These map roughly to the natural review checkpoints — each can be reviewed
and shipped independently of the next.
